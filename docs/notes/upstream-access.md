# 模型路由与上游访问

## 问题

网关背后有多个上游（不同供应商），调用方只指定模型名。网关要把请求送到对的上游、带上对的上游密钥，并且保证两点：上游密钥不外泄；上游出错时，调用方拿到的错误格式统一、不带敏感信息。

## 方案

**配置。** 一个 YAML 文件（示例见 `config.example.yaml`）列出上游和模型。上游密钥不写在文件里，只写环境变量名（`key_env`），`config.Load` 加载时读出，变量没设置就启动失败。上游地址同样可以只写变量名（`base_url_env`）——私有的中转地址往往和密钥一样不该进仓库。解析时开了 `KnownFields(true)`，拼错的字段名直接报错，而不是被悄悄忽略。

**路由。** 每个模型固定对应一个上游。`relay.New` 启动时建好"模型名 → 上游地址和密钥"的 map，请求时查一次。模型不存在返回 404 `model_not_found`，请求不会发往任何上游。`GET /v1/models` 返回配置里的全部模型。

**只带上游密钥。** 发往上游的请求只设置 `Content-Type` 和 `Authorization: Bearer <上游密钥>`，调用方的请求头（包括它自己的 Authorization）一概不转发。

**错误转换。**

| 上游的情况 | 调用方收到 |
|---|---|
| 401 / 403 | 502 `upstream_auth_failed`，丢弃原始响应体，因为里面可能带着密钥片段 |
| 其他非 200，响应体是 OpenAI 格式 | 同样的状态码和 error 对象；`code` 不是字符串时只保留 message 和 type |
| 其他非 200，响应体不是 OpenAI 格式（例如代理层的 HTML 错误页） | 同样的状态码，`upstream_error` |
| 流式请求却收到非 SSE 的 200（有的上游出错时照样回 200） | 502，error 对象的处理同上 |
| 连接失败 | 502 `upstream_error`，错误信息里不带上游地址 |
| 返回 200 后响应中途断开 | 非流式返回 502 `upstream_interrupted`；流式见 [SSE 流式转发](sse-relay.md) |

**HTTP 客户端。** 所有请求复用一个 `http.Client`，Transport 从默认值克隆后改两处：`MaxIdleConnsPerHost` 从 2 调到 100，否则并发一高就要不断新建连接；`ResponseHeaderTimeout` 设为 10 分钟。不设 `Client.Timeout`，它会截断长流。

## 取舍

- **每个模型只走一个上游，不做故障转移。** 故障转移要处理"首个事件之前失败才能切换"、熔断和半开探测，复杂度高，留到以后。
- **按 `Content-Type` 判断流式响应是不是 SSE。** 这是最直接的信号，不用先读响应体去猜；代价是如果某个上游的流式响应把 `Content-Type` 写错了，网关会把它当成出错。
- **状态码透传。** 上游的 429、503 原样交给调用方，OpenAI SDK 会按状态码自动重试；代价是调用方从状态码上分不清 429 来自网关还是上游。
- **`owned_by` 填上游名。** 调用方能看出模型由哪家提供，这不算敏感信息。
- **配置只在启动时读一次。** 改配置要重启，换来的是路由表只读、不需要加锁。

## 延伸问题

- 上游密钥要轮换怎么办？现在只能重启；可以改成定期重读，或者接入密钥管理服务。
- 同一个模型挂多个上游、按权重分流，数据结构怎么变？路由表的值从一个上游变成一组带权重的上游，每次按权重随机挑一个。
- 上游返回的 429 和网关自己限流的 429 错误码可能相同（都叫 `rate_limit_exceeded`），调用方要区分的话，可以把上游的 429 转成 503。
- 为什么 400 和 404 在转发之前就返回，不交给上游判断？这样明显不合法的请求不会产生上游调用，也就不会产生费用。
