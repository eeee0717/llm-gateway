# SSE 流式转发

## 问题

流式请求里，上游用 SSE（Server-Sent Events）一段一段地返回回答。网关夹在中间，要同时做到四件事：

1. 调用方收到每个事件的时间尽量接近直连上游，不能攒一批再发；
2. 转发的内容保持原样，调用方的 SDK 感觉不到中间多了一层；
3. 从流里读出用量，而上游默认不在流里报告用量；
4. 上游中途出错时，让调用方知道回答被截断了，而不是以为回答本来就这么短。

## 方案

**按事件读取，原样转发。** `internal/sse` 的 `Reader.Next` 每次读出一个完整事件（以空行结尾），同时给出两样东西：`Raw` 是事件的原始字节，转发时原样写出；`Data` 是 data 行的内容，供网关解析。网关只解析、不改写，调用方收到的字节和上游发出的一样。

**每个事件写完就刷新。** `relayStream` 每写完一个事件就调用 `c.Writer.Flush()`。不刷新的话，`net/http` 会把数据留在缓冲区里，攒满了才发给调用方。上游返回 200 之后先刷新一次响应头，调用方立刻知道请求已被接受。

**强制要用量，再把多要的剥掉。** 流式请求转发前，`forceIncludeUsage` 在请求体里打开 `stream_options.include_usage`，上游就会在 `[DONE]` 之前多发一个只含 usage、`choices` 为空的事件。调用方自己没要求的话，这个事件不转发，调用方看到的流和直连时一样。请求体按 `map[string]json.RawMessage` 解析再写回，其余字段的语义不变（字段顺序、空白和转义方式可能和原文不同）。

**上游中途出错时补一个错误事件。** 响应头已经发出，状态码改不了了。所以流在 `[DONE]` 之前结束时（连接中断，或者上游没发 `[DONE]` 就关闭），网关补发一个 `data: {"error": {...}}` 事件。OpenAI 官方 SDK 读到带 error 的事件会抛异常，调用方由此知道回答被截断。

**读到 `[DONE]` 后继续读到 EOF。** 不马上返回，是为了把响应体读完：HTTP/1.1 下响应体没读完就关闭，这条到上游的连接就不能复用，下一个请求得重新建连，HTTPS 还要重新握手。

## 取舍

- **每个事件都做一次 JSON 解析。** 为了拿到用量和估算用的文本，每个事件都要 `json.Unmarshal`。一个事件只有几百字节，解析的耗时和上游生成一个 token 的间隔相比可以忽略；换来的是代码简单，不用写字节级的匹配。网关整体多出的延迟由 M4 的压测给出。
- **不改写 `"usage": null`。** 开了 `include_usage` 之后，OpenAI 会在其余每个事件里都带上 `"usage": null`。要去掉它就得重新序列化每个事件，丢掉"原样转发"的简单；而 SDK 对 null 和字段缺失的处理一样，所以只剥离那个独立的 usage 事件。调用方看到的流和直连在语义上等价，但不是逐字节相同。
- **换行只认 `\n` 和 `\r\n`。** SSE 规范还允许单独的 `\r`，但 OpenAI 兼容的上游都不用，为它多写代码不值得。
- **流末尾不完整的事件直接丢弃。** 这是 SSE 规范的要求；随后网关会把这种情况当成上游中途出错处理。
- **读到 `[DONE]` 后继续读到 EOF，前提是上游会正常结束响应。** 如果上游发完 `[DONE]` 却不关闭连接，这个请求会一直挂到调用方超时断开。正常的上游不会这样，所以没有为此加计时器。
- **上游自己发了错误事件再断开时，调用方会收到两个错误事件。** SDK 读到第一个就抛异常，第二个无害，所以没有专门去重。

## 延伸问题

- 调用方读得很慢时会怎样？TCP 发送缓冲区满了之后，`c.Writer.Write` 会阻塞，网关随之停止读上游，上游那边的 TCP 窗口也会被填满。这就是 TCP 的背压，网关不需要自己再做缓冲。
- 为什么不设 `http.Server.WriteTimeout`？它从读完请求头开始计时，覆盖整个响应，几分钟长的流会被它截断。
- 网关前面如果有 nginx，要关掉它的响应缓冲（`proxy_buffering off`，或响应头 `X-Accel-Buffering: no`），否则刷新只到 nginx 为止。
- 包装 `gin.ResponseWriter` 的中间件为什么要实现 `Unwrap()`？`http.ResponseController` 靠 `Unwrap` 一层层找到底层的 `http.Flusher`，而 `Unwrap` 不在 `gin.ResponseWriter` 接口里，嵌入接口得不到它。本项目的访问日志只读 `c.Writer.Status()`，没有包装 Writer。
- 上游用 HTTP/2 时有什么不同？流是多路复用的，提前关闭响应体只会重置这一个流，不影响同一连接上的其他请求。
