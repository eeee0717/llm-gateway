# 余额只存在 PostgreSQL，Redis 只做鉴权缓存和限流

余额是账，只能有一份权威数据，所以只存在 PostgreSQL 里。预扣是一条带条件的 UPDATE：余额够、并且 Key 没有被禁用才扣，用 RowsAffected 判断成败，而不是先查再改。同一个 Key 的并发预扣由行锁排队，多个网关实例之间不需要额外协调。结算和用量记录在同一个事务里提交。

Redis 只做两件事，里面的数据丢了都能重建：

- **鉴权缓存**：Cache-Aside，TTL 5 分钟。缓存里只放 Key 的身份信息和限流参数，不放余额。禁用 Key 时先改 PG，再删缓存。并发的缓存回填可能把禁用前的旧值写回去，最长持续一个 TTL；但预扣的条件 UPDATE 会检查禁用状态，被禁用的 Key 照样过不了预扣，旧缓存只影响不计费的 `GET /v1/models`。
- **限流**：按 Key 的令牌桶，用自己写的 Lua 脚本在 Redis 里一次完成补充和扣减，多个网关实例共享同一个桶。

演进方向（不实现）：同一个 Key 的并发极高时，PG 的行锁会成为热点，可以把余额搬进 Redis、用 Lua 预扣，再定期同步回 PG 并核对。代价是出现两份余额，要处理两者不一致；目前的并发量用不到。
