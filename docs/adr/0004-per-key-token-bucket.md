# 按 Key 的令牌桶限流：额度存在 PostgreSQL，当前时间由网关提供

限流要按调用方来算，而网关会跑多个实例，所以桶的状态必须是共享的：放在 Redis 里，用一个 Lua 脚本一次完成补充和扣减，避免"先读再写"的竞态。桶容量等于每分钟的额度，补充速率是额度除以 60，允许攒下一分钟的突发。

**额度是每个 Key 一个值，存在 `api_keys` 表里。** 加一列 `rpm_limit`，为 0 时用配置里的默认值。不同调用方给不同额度是常态，而额度和 Key 的身份是一起查出来的，跟着鉴权缓存一起进 Redis，限流时不用再查一次数据库。代价是多一次迁移，以及管理接口多一个字段。

**当前时间由网关作为参数传给 Lua 脚本**，而不是在脚本里调 `redis.call('TIME')`。这样测试可以注入固定的时间，"放行了多少个请求"就是一个确定的数字，而不是一个受机器快慢影响的范围。代价是多个实例之间有时钟漂移：NTP 之下通常在十毫秒级，而桶是按分钟补充的，这点偏差只会让补充的令牌多出或少掉万分之几个。如果哪天时钟不可信，改成脚本里取 Redis 的时间即可，桶的数据结构不用动。

**Redis 不可用时放行**，见 [ADR-0002](0002-balance-in-postgres-only.md)：脚本执行失败时请求照常通过，只记一条日志。限流是保护上游的，不是记账的；余额不在 Redis 里，所以放行也不会超扣。
